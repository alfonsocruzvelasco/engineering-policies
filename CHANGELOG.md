### Changed
- Refreshed GPT-6 Astra metadata and operational guidance across policy surfaces: added Astra model identity/limits/pricing (including >272K long-context full-request repricing), clarified ChatGPT included-allowance use vs separately billed API/extra-usage paths, and recorded OpenAI Critical cybersecurity capability posture without weakening SPEND FREEZE or existing containment/verification controls (`AGENTS.md`, `model-registry.md`, `approved-ai-tools.md`) (2026-09-04).
- Refreshed Muse Spark 1.3 metadata and availability posture: `model-registry.md` now supersedes Spark 1.2 with Spark 1.3/Contributor IDs, pricing, context, max-reasoning/open-weights status, and Contributor data-use caveat; `AGENTS.md` now mirrors the operational status concisely; SPEND FREEZE restrictions remain unchanged and Contributor use remains restricted for portfolio/private/repository code (`AGENTS.md`, `model-registry.md`, `approved-ai-tools.md`, deferred OpenSpec note) (2026-09-03).
- Refreshed Claude Fable/Mythos 5.1 metadata and availability in the model registry using Anthropic primary documentation: canonical model IDs, pricing (including cache-read reduction), platform availability, and routing/fallback caveats are now current, while SPEND FREEZE authorization remains unchanged (listing/availability does not authorize use); `approved-ai-tools.md` freeze lists now explicitly include Fable 5.1/Mythos 5.1 to avoid ambiguity (`model-registry.md`, `approved-ai-tools.md`) (2026-09-02).
- AI learning protocol now explicitly adds a proportional pre-delegation hypothesis/prediction step for learning and portfolio skill-building tasks (`attempt/hypothesis -> prediction -> agent assistance -> evidence review -> independent reconstruction`), while leaving routine mechanical work unchanged (`ai-workflow-policy.md`) (2026-08-31).
- Agent governance now explicitly distinguishes behavioral fences from technical security containment, preserves sandbox/isolation controls despite model-capability improvements, and adds proportionate progressive enforcement for repeated or high-impact failures while avoiding rule-system accretion (`ai-workflow-policy.md`, `security-policy.md`) (2026-08-31).
- Database schema documentation now explicitly treats ERDs and diagram-as-code artifacts as optional derived documentation rather than schema authority; text-based/version-controlled representations such as DBML may be used when they materially improve design or review, while authoritative DDL/migrations remain the source of truth and sensitive schema/data must not be exposed through public diagram services (`folder-organisation-policy.md`) (2026-08-29).
- Agent-facing configuration now has an explicit lifecycle: `AGENTS.md`, `CLAUDE.md`, skills, hooks, MCP configuration, memories, and equivalent instructions must continue to justify their operational value after material model/harness/repository changes; obsolete or duplicated guidance should be simplified, while critical machine-checkable requirements should prefer deterministic enforcement over prose alone (`ai-workflow-policy.md`) (2026-08-28).
- Security policy now treats side-effecting notebook/project/MCP metadata as potentially executable untrusted input and clarifies that loopback binding reduces exposure but does not authenticate callers; sensitive local HTTP APIs require proportionate caller/origin controls in addition to 127.0.0.1 binding (`security-policy.md`, `development-environment-policy.md`) (2026-08-27).
- External contributions now require compliance with the upstream project's current AI/LLM contribution policy; upstream restrictions override the normal internal AI workflow, while third-party project indexes remain discovery aids rather than sources of permission (`ai-workflow-policy.md`) (2026-08-27).
- Agent evaluation now treats run-to-run variance according to task type: exploratory coverage tasks may use pooled independent runs while still reporting per-run consistency, precision, and triage cost; deterministic tasks must not hide poor reliability behind pooled pass@k results (`ai-workflow-policy.md`) (2026-08-27).
- Agent evaluations now treat performance as a property of the model-harness configuration rather than the model alone; model-specific harness compensations require evidence and re-evaluation after material model/harness changes so obsolete orchestration does not accumulate (`ai-workflow-policy.md`) (2026-08-26).
- Claude quota conservation now distinguishes fresh-context clearing from continuity-preserving compaction, uses `/usage` diagnostics for long-context/cache/feature attribution, limits unnecessary background quota consumers, and defines evidence-first diagnosis for unexpected usage (`ai-workflow-policy.md`) (2026-08-23).
- Claude subscription quota conservation now distinguishes included usage from incremental spend and adds bounded model/effort/context/subagent discipline without weakening validation or the active SPEND FREEZE (`approved-ai-tools.md`, `ai-workflow-policy.md`, `AGENTS.md`) (2026-08-23).
- Temporal semantics are now explicit across database, Python, API/logging, naming, and tests: real instants are timezone-aware and UTC-oriented; PostgreSQL real instants use TIMESTAMPTZ; local civil schedules retain IANA timezone identity; naive/platform-local timestamps are prohibited for persisted event instants; DST-sensitive local scheduling requires explicit tests (`production-policy.md`, `language-policies.md`, `naming-policy.md`, `testing-policy.md`) (2026-08-20).
- Text encoding is explicit at external boundaries with UTF-8 as the default unless an external contract requires otherwise (`production-policy.md` §6.1); source/config Unicode security covers bidi controls, invisible characters, confusables, and mixed-script identifiers without restricting legitimate Unicode data (`security-policy.md` §9.7) (2026-08-20).
- Fail-closed network isolation for tool/code-executing agent test and evaluation workloads (`agent-egress-and-memory-isolation-policy.md`); explicit MCP server inventory/allowlisting with remote MCP treated as a mutable trust boundary (`security-policy.md` §8). No Cloudflare Workers-specific rule: existing secrets, least-privilege, and isolate defense-in-depth controls remain sufficient (2026-08-20).
